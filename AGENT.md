## 1. Product In One Sentence

Luminary is a connected daily companion. Spotify provides an attributed listening recap, while Luminary-owned wellbeing signals connect commitments, journaling, meals, health, money, and the nightly ritual without treating listening data as a mood profile.

## 2. Non-Negotiable Principles

1. **Ritual-first.** The nightly check-in is the product. Every other module supports or enriches it.
2. **No-line rule.** Do not use 1px borders for sectioning. Use surface shifts, spacing, or approved ghost outlines.
3. **One blue.** `palette.primary` (`#8cacff`) is the universal active accent.
4. **Tokens only.** No hardcoded component colors, spacing, radii, or font sizes. Use `@luminary/design-system`.
5. **Tone passes through `TONE.md`.** No lorem ipsum, no stock mobile copy.
6. **Mood is continuous.** Store timestamped `mood_events` with source; derive daily headline mood in the app.
7. **Soft streaks.** Habit consistency is a sliding-window band, not miss-a-day-and-die.
8. **RLS on every user-scoped table.** Keep schema additions scoped to `auth.uid()`.
9. **Personality before polish.** Every screen should feel written by Luminary, not generated by a settings template.

## 3. Resolved Product Decisions

- Visible tabs: Home, Journal, Health, Money. Meals is implemented as a product surface and can be reached from Home/module flows; navigation should stay intentional rather than adding tabs casually.
- Center FAB launches the `/ritual` modal route.
- Habits live inside Home and the ritual, not as a standalone tab.
- Health, Money, and Meals are part of Mari's MVP and should be functional, not hidden behind placeholder locks.
- Spotify mood reject CTA is exactly "Not quite right."
- Auth is Supabase Auth. RLS uses `auth.uid()` directly.
- Mood vocabulary is defined in `mobile/lib/mood.ts` and the initial Supabase migration.
- `mobile/app.json` is the authoritative Expo config. Current package id is `app.luminary.mobile`.
- Expo typed routes are disabled in `mobile/app.json` because generated route unions broke in this Windows monorepo shape.

## 7. Coding Standards

- TypeScript strict. Avoid `any`; if unavoidable, explain why.
- Use `@/` for mobile-internal imports and `@luminary/design-system` for tokens.
- Function components and hooks only.
- Styles live in `StyleSheet.create`.
- Every Pressable needs an accessibility role and useful label where practical.
- Touch targets should be at least 44x44.
- Errors should not disappear: warn, surface a user-friendly note, or queue safely.
- External responses and trust-boundary data should be validated with Zod or typed parsing.
- Do not copy `docs/originals/luminary.jsx` into mobile. Translate the intent into React Native.

## 8. Workflow

- Branches: `main`, `develop`, `preview/mobile`, `feat/<name>`, `fix/<name>`, and `docs/<name>`.
- Conventional commits: `feat:`, `fix:`, `docs:`, `chore:`, `refactor:`, `test:`.
